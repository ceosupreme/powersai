## Proposal Generator — Plan (revised)

Branded one-pager built from real leak numbers, cloning the Growth Audit print-to-PDF pattern. Consumes `leak_stack_runs` — never recomputes dollar math.

### (a) Footprint resolution path (best-effort, in order)

1. Explicit `footprint` arg passed into the builder launch (from CompanyDetail/LeakStack context).
2. `venues.source_lead_id` → look up that `inbound_leads` row → `qualifier_data->>'operation_footprint'`.
3. Most recent `inbound_leads` row matching `company_id` (via crm) or `venue_id`, ordered by `created_at desc`, whose `qualifier_data->>'operation_footprint'` is non-null.
4. Else `null` → builder shows a manual footprint picker (solo_owner / small_crew_2_5 / crew_6_plus / multi_location).

Implemented in `useProposalFootprint(companyId, venueId, explicit?)`.

### (b) Leak ledger consumption (zero recomputation)

- Query latest `leak_stack_runs` row for `venue_id` (`order by computed_at desc limit 1`).
- Split `results` jsonb by `risk_type`: `captured_revenue` → main ledger; `avoided_loss` → separate "Avoided-loss exposure" line group.
- Each row reads `name`, `monthly_dollars`, `severity`, `benchmark`, `reason` verbatim.
- Footnote generated by summarizing distinct `inputs[].source` values (mapped via `SOURCE_LABEL` from `src/lib/leakStackFormat.ts`), plus a comma list of `inputs_basis` keys: `"estimates — basis: Live signals, Vertical defaults. A live install uses your numbers."`
- Manual leaks (added when no run exists, or alongside a run) stored in `content.manual_leaks[]` with `manual: true`, rendered with a "provided manually" pill, excluded from any run-derived totals.

### (c) Render pattern to clone

From `src/components/growth-audit/reports/`:

- `ReportRenderer.tsx` → new `src/components/proposals/ProposalRenderer.tsx` (`report-print-root`, `report-avoid-break`, sticky non-printing header).
- `print.css` → new `src/components/proposals/print.css` (reuses `@media print` shell; adds proposal tokens: bone `#F7F4EC`, forest `#0E5236`, rust `#B5431E`, gold `#C9A24B`; Bricolage Grotesque / Instrument Sans / IBM Plex Mono via `<link>` in the wrapper).
- `ReportsView.tsx` / `ReportBuilderDialog.tsx` → shape for the `ProposalBuilderDialog.tsx` + inline preview harness (Back / Print buttons calling `window.print()`).
- `snapshot.ts` / `types.ts` → equivalent `types.ts` for the proposal `content` jsonb.

### 1. Schema (single additive migration)

**`proposals` table**

- Columns: `id uuid pk default gen_random_uuid()`, `company_id uuid null → crm_companies(id) on delete set null`, `venue_id uuid null → venues(id) on delete set null`, `leak_stack_run_id uuid null → leak_stack_runs(id) on delete set null`, `title text not null`, `content jsonb not null default '{}'`, `status text not null default 'draft' check (status in ('draft','sent'))`, `created_by uuid null → auth.users(id)`, `created_at`, `updated_at` + `handle_updated_at` trigger.
- GRANTs: `SELECT, INSERT, UPDATE, DELETE` to `authenticated`; `ALL` to `service_role`. No `anon`.

**RLS (tightened per feedback #1)**

- `SELECT`: `NOT public.has_role(auth.uid(),'client') AND (public.has_role(auth.uid(),'admin') OR (venue_id IS NOT NULL AND public.user_can_access_project(venue_id)))`.
  - Consequence: **company-only proposals (venue_id null) are admin-read-only.** Owner/GM/lead see only proposals attached to a project they can access.
- `INSERT`, `UPDATE`, `DELETE`: **admin-only** (`public.has_role(auth.uid(),'admin')`), matching the admin-CRUD convention this feature cites (SettingsAutomationBundles / SettingsOutreachTemplates).

**Qualifier config seed — resolved per feedback #2 (path b)**

Existing select-type qualifier fields do NOT carry an options store (verified: `FormQualifier.tsx` renders `field_type==='select'` as a plain `Input`, no options attached to `project_type_qualifier_fields`). So option (a) does not exist — taking the **explicit prompt-edit path**:

- Insert one row into `project_type_qualifier_fields` for `project_type='home_services'`: `field_key='operation_footprint'`, `field_label='How big is the operation?'`, `field_type='select'`, `is_shared=false`, `sort_order` after existing rows.
- Add an `operation_footprint_options` jsonb key on the existing `project_type_qualifier_config` row for `home_services` (mirrors `urgency_options`; no schema change). Canonical keys: `solo_owner | small_crew_2_5 | crew_6_plus | multi_location`, each with a `label` and short `guidance` string. Seed comment: adding new keys is safe (no DB CHECK) but requires updating `src/components/proposals/engineDefaults.ts` in the same change.
- **Edit `supabase/functions/_shared/qualifier-prompt.ts`** to (i) load `operation_footprint_options` in `loadQualifierContext`, (ii) inject a soft-ask block into `buildSystemPrompt` styled like `urgencyBlock` — instructing the agent to figure out which key fits and pass it as `qualifier_data.operation_footprint`. No changes to `submit_qualified_lead` tool schema; `operation_footprint` rides inside `qualifier_data` (already `additionalProperties: {type:'string'}`). Optional in every path — missing values never block submission.

### 2. Hooks / data

- `src/hooks/useProposals.ts` — list by `company_id` / `venue_id`, create, patch content, `setStatus`, delete. TanStack Query key `['proposals', {companyId, venueId}]`.
- `src/hooks/useProposalFootprint.ts` — resolution path (a).
- Reuse `useLatestLeakStackRun`, `useServicePackages({activeOnly:true})`.

### 3. Builder (`ProposalBuilderDialog.tsx`, admin-only)

Sections:

- Prospect + intro line (prefills `prospect_name` from company / venue).
- Footprint chip row (auto-picked with source label; overrideable).
- Engines: 4 toggles defaulted from footprint — `solo_owner→[acquisition]`, `small_crew_2_5→[acquisition, retention]`, `crew_6_plus→[acquisition, retention, command_center]`, `multi_location→[acquisition, retention, command_center, delivery]`. Display: Acquisition Engine / Retention Engine / Command Center / Delivery Engine.
- Leaks: from latest run — checkboxes, top 3 preselected (`severity==='headline'` first, then by `monthly_dollars`). "Add manual leak" appends to `manual_leaks[]`. No run → manual-only mode with a prominent banner.
- Package: `<Select>` of real `service_packages` (name + formatted `price_cents`); `price_display` text input prefilled from selection, editable. Preselect only when a package name plainly matches the footprint tier (case-insensitive substring: "solo", "crew", "multi", etc.). Never fabricate rows.
- Next-step line.
- Save → `proposals` row, `status='draft'`; "Preview / Print" launches the renderer harness.

### 4. Renderer + entry points

- `ProposalRenderer` wraps `report-print-root`, sticky non-printing header (Back / Print).
- Sections top-to-bottom per spec: Header eyebrow (`PROFIT LEAK PROPOSAL`), THE LEAK LEDGER (rust mono `/mo`, avoided-loss block, honest-estimate footnote from `inputs_basis`), HOW IT GETS PLUGGED (Detect→Dollarize→Assign→Verify + kicker), WHAT GETS INSTALLED (package + gold-check engines), NEXT STEP.
- Draft watermark: fixed diagonal `DRAFT` at low opacity when `status==='draft'`; removed when `'sent'`.
- Entry points (**admin-only per feedback #1**):
  - `CompanyDetail.tsx`: "Proposals" list card with "Generate proposal" button and per-row "View / Print" + draft/sent toggle. Button and row actions hidden unless `useUserRole` reports admin. Non-admin CRM users see nothing here.
  - `src/pages/LeakStack.tsx`: header action "Generate proposal for this project" — hidden unless admin, even though `leak_stack` pageKey is enabled for owner.
- Copy rule: rendered document says "your business"; internal UI (dialog, list card) says "project".

### 5. Permissions

Builder is a dialog on existing pages, renderer is inline → **no new route or pageKey**, no `role_page_defaults` seed. Client role fully blocked by RLS; non-admin writes fully blocked by RLS + UI gate.

### 6. Guardrails

- Additive migration; no changes to `leak_stack_runs`, `service_packages`, or existing qualifier code paths (only `qualifier-prompt.ts` extends with an optional soft-ask).
- All dollar figures render from `leak_stack_runs.results[*].monthly_dollars` or explicit `manual_leaks[].monthly_dollars` (flagged manual). No arithmetic in renderer.
- Footnote and source pills survive to print via `report-print-root` + existing `-webkit-print-color-adjust: exact`.
- `tsgo --noEmit` clean.
