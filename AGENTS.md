# Project architecture rules

- Business Path progress and proof validation live in `src/lib/businessPath.ts`, loaded and saved only through `useBusinessPath`; admin and manager screens share `BusinessPathTab` so counts, completion, and proof rules agree. The map is always available to assigned brand teams; settings saves preserve the legacy visibility value.
- Brand-team viewer labels, readiness, plan ordering and Pacific-week counts live in `src/lib/brandTeam.ts`; admin team view uses URL-scoped presentation identity and read-only child controls, never impersonated write credentials.

- Radar reads existing research tables through paginated, RLS-respecting queries and shares the content_pipeline permission; it never writes research data or introduces a separate permission model.

- Public-site media replacements use named entries in `src/config/studioMedia.ts`; do not build media-management UI or storage because the owner replaces assets through conversation uploads.
- Published version-2 industry navigation reads through `usePublishedVerticalLanders`; do not maintain a second hard-coded market list because database rows are authoritative.
- Pricing (/pricing, shown as Packages) owns the starter packages and the build-your-own service menu, read from starter_packages and service_pages rows; package sends use the shared submit-inbound-lead intake and online checkout stays on industry pages. Websites and Home link to it so pricing stays consistent.
- Published V2 industry pages render the database `layout.sequence` and `layout.interaction` in the shared homepage visual system; keep copy and ordering row-driven so markets and Spanish overrides stay editable without per-market branches.
- Brand and Marketing sales routes own their six-section layouts in their respective page files and share `Inquiry`'s servicePage context; this keeps their distinct compositions independent while preserving one lead workflow.
- Systems and Publishing sales routes own their six-section layouts and share `Inquiry`'s servicePage context; this keeps their workflow and product compositions distinct without duplicating lead handling.
- Industries reads published V2 rows including layout media and interaction for its visual directory; Work uses the published-project adapter and URL `type` filters so neither page duplicates editorial data.
- Local Vite proxies only Lovable CDN asset paths to this project's preview host; otherwise media pointers return the Vite HTML fallback instead of images during local visual QA.
- Case studies use published fields/media; Hire uses that adapter and inquiry. Free Check and Thank-you retain protected logic. Public motion is progressive enhancement: visible by default, in-view animated, reduced-motion static.
- Public builds prerender marketing HTML then hydrate React; the publish step saves each page as React's first draw and marks it `data-hydrate` only after a trial hydration matches, so other pages redraw instead; failed dynamic renders retain route-specific SPA metadata fallbacks.
- The homepage opening owns a dedicated header and visual scope; shared `StudioHeader` remains authoritative on every other public route so homepage art direction cannot alter sitewide navigation.
- Owner work rules (Claude steps hidden, depends_on gating, stale channels, pipeline step status) live in `src/lib/ownerWork.ts` and are shared by Next 10, Waiting on me, Portfolio cards, the brand workspace and the pipeline page so the lists never disagree.
- Every Create pipeline action goes through `src/lib/pipelineComposer.ts` and the shared `CreatePipelineDialog`; job advancement stays in the database trigger, so the front end only refetches after step changes.
- Playbook status words (Planned, Written, Thin) come only from `src/lib/playbookStatus.ts`, and playbook-kind production jobs are excluded from brand job lists; every screen shares one definition so shelves, brand coverage and pipelines never disagree.
- Brand Setup map rules (why line, minutes words, top-3 pick, Foundation rows, traffic check, media kit steps, screenshot match, setup brief) live in `src/lib/brandSetup.ts`; the Setup tab, Channels tab and Portfolio read `v_brand_asset_map`/`v_brand_setup_summary` so states are never recomputed in the browser.
- The owner's HQ Guide is Markdown in `src/content/guide` (NN-slug.md with the header comment), parsed only by `src/lib/hqGuide.ts`; the /guide page and the PDF copy are both built from those files, so when a screen, label or flow changes, update the matching file instead of writing guide text anywhere else.
- Brand dashboard numbers (status chip, output, audience, money, latest work) come from `src/lib/brandPulse.ts` via the batched `useBrandPulses`; the Overview tab and Portfolio cards both read it so a brand's status never disagrees between screens.
